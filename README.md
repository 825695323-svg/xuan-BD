# xuan BD

本机数据处理与导入应用，提供基础特殊数据算法。范围为来源采集、转换、解析、清洗、标注、核对、结构化、候选交接和数据库导入，以及已有指标和分钟／日线加工。内置代理、权限、预算、任务恢复和设置为这些数据任务服务。金融研究、通用模型接口、独立风险、交易和模型回测已从本应用范围拆出，见[独立模块规划](../../xuan%20harness/规划/README.md)。

## 当前数据交接首版

2026年10月23日已在原应用和原用户测试实例采用 `/v3/data-entry`（第三版数据入口）与 `wfd.data-service/v1`（首版通用数据服务契约）。现有会话可按所选材料及已有产品引用／新声明准备候选、明确提交、返回真实操作者审批引用、核对原请求和固定读回。生成样本完成两次表提交与父快照衔接，未知二进制只保管并返回缺口；最终重启后的原请求与两快照固定读回一致，未新增提交。

原件在权限与容量内接收，浏览器上传25 MiB（兆二进制字节）、受控文件引用256 MiB；预览预算独立。正式产物首版限五种字段表示的完整表快照，明确 CSV（逗号分隔表）／JSON（对象表示法）表格解析与已有受控转换产物可接原证据，不代表任意格式可解码。当前授权仅精确 `bd.user_test`（BD用户测试命名空间）／`user_test`（用户测试用途），正式写入及历史／增量／流式／文档音视频产品未启用；原分钟／日线原包没有导入。完整现状与限制见[实施与验收](../规划/实施与验收.md#当前状态与未完成)，证据统一见[本批总回执](../../xuan%20harness/资料与历史/说明与记录/运行框架/施工记录/通用声明式交接-20261023/README.md)。

## 开始工作前：先读取本机实际配置

进入工程、启动应用、换设备或恢复依赖本机资源的工作时，先按以下来源读取实际执行设备的配置。先核对当前值，再与已采用基线比较；无基线时只称首次核对，不称未变。浏览器设备和执行设备分别核实。

| 引用入口 | 本机权威来源 |
|---|---|
| 启动定位 | `platform/resources/bindings.ts` 的 `launcherPath()`（定位文件位置）与 `locateRuntimeRoot()`（运行根解析）；优先明确 `--runtime-root`，其次 `XUAN_HARNESS_HOME`（运行根环境变量），再读取 `--launcher` 或本系统用户目录下的 `Xuan Harness/launcher.json`（既有定位记录）。 |
| 运行身份和资源位置 | 运行根的 `.xuan-runtime.json` 与 `config/machine.bindings.json`，由 `ResourceBindings`（资源绑定）解析逻辑资源键、身份、修订与可达性。 |
| 组件实际配置 | 绑定的 `config`（配置资源）内模型、工具、来源配置与 `connections_registry`（连接登记资源）；凭据只保留安全引用。 |
| 本机执行资源 | 本工程 `resources/bundled/manifest.json`（随包清单）及已登记程序、模型和浏览器引用；通过 `ProcessRuntime`（已登记程序核验入口）执行。 |

所有随设备、系统、用户目录、挂载或安装位置变化的配置，只在工程中保留逻辑引用、权威来源与解析入口；实际值由本机配置提供。比较持久值和进程生效值，区分外部覆盖、待重启与待迁移；旧任务继续沿原配置身份、连接和请求核对。读取配置不授予安装、迁移、登录或扩权，无关变化不阻断。完整规则见[前端与配置](../规划/代理与运行/前端与配置规划.md#设置和设备配置)。

## 启动与开发

同一应用提供网页、会话和数据接口，日常地址为 `http://127.0.0.1:4317`。

- macOS（苹果系统）：`start-macos.command`；独立窗口：`启动窗口.command`。
- Windows（视窗系统）：`start-windows.cmd`；真实 Windows x64 实机仍待验收。
- 开发：`npm run build`（类型核对并构建），再 `npm run web`（启动服务）。
- 指定定位文件：启动参数 `--launcher=绝对路径`。
- 工作台：`npm run workspace -- status`（查看同一应用状态），也保留原停止、恢复、任务及会话命令。

启动脚本使用随包 Node.js（运行程序）。关闭网页不停止服务；终止信号等待自有任务收束。原状态所有者锁不按锁龄或进程编号自动接管。普通源码修改只做定向验证、构建和同一应用重启；持久格式、真实资源、搬迁或明确清空状态时才处理受影响数据与恢复材料。

## 数据和算法边界

来源插件取得原件与回执，收集模块承担后续五步处理和候选交接。当前首批为用户所选一分钟行情与每日日线原包，字段及缺项见[首批登记](../规划/数据与来源/首批分钟与日线登记.md)，尚未全量处理或入库。分钟聚合、复权与历史可得性须先有时间、单位、基准、版本和产品合同；已有原值不能替代语义确认。

基础算法范围见[规划](../规划/数据与算法/基础数据算法规划.md)。原 MA（移动平均）、MACD（指数平滑异同移动平均）和严格看涨吞没方法源码保留；此前注销的运行登记、撤销的计算资产绑定和清空的旧测试不因改名恢复。计算结果与正式保存分别认定，不恢复旧固定快照。新算法或新输入须沿受控登记、实际绑定、授权和验证入口接入。

多个数据库连接分别管理实例、位置、用途、协议、凭据引用和权限。本应用不接管 WFD（世界金融数据库）的正式存储治理，也不因改名启用正式写入；成功以数据库真实 `committed + commit_id + snapshot_id`（提交及其身份）和固定读回认定。未知结果沿原任务与连接查询，不盲目重发。

## 位置与身份兼容

一个应用运行身份、一个入口，个人和工作台保留各自逻辑状态库。`config`（配置）、`state`（状态）、`task_files`（任务文件）、`model_resources`（模型资源）、缓存、临时、下载、浏览器及连接登记均由资源绑定独立解析，默认布局只作初值。

工程显示名称和目录为 xuan BD，包名为 `xuan-bd`；现有运行标记 `application=xuan-harness`（应用身份类型）、系统用户目录的旧定位记录、`XUAN_HARNESS_HOME`（运行根环境变量）、`/api/harness`（接口前缀）及已有动作标识保留，以承接已有配置、客户端和任务。它们不代表原八模块范围继续存在。数据代理规则和数据服务版本按本次职责修订；旧任务保留冻结版本，不套用新规则继续。无需为改显示名另建运行环境或复制状态。

随包执行资源变更通过 `scripts/adopt-bundled-resources.ts`（随包资源采用入口）核对清单、原身份与修订。本次父目录和源码的同卷改名经专用维护事务核对原节点、字节、引用和未决任务后采用，绑定修订17；该一次性实现按用户要求不保留，配置事务回执见本次收敛记录。数据库接线沿既有维护入口，具体机器值不写回文档。新设备准备入口是 `scripts/prepare-runtime.ts`，目标设备配置必须明确提供。

开发规则见 [AGENTS.md](AGENTS.md)，产品实际加载的规则是 [数据代理规则](modules/agent/instructions/AGENTS.md)。现行规划从[规划入口](../规划/README.md)进入；当前事实、未完成项和实施条件统一见[实施与验收](../规划/实施与验收.md)，原始来源见[来源依据](../规划/来源依据.md)；本次改名、清理、恢复依据与验证见[收敛记录](../../xuan%20harness/资料与历史/说明与记录/运行框架/施工记录/xuan-BD收敛-20261023/README.md)。历史记录保留原时点和范围，不能替代当前运行事实。
