# 增量范围与核对

## 确定本轮基线

1. 确认来源、要补的数据或文件类别、业务日期范围和本地目标。没有明确来源时先解决来源，不默认扫描所有分享。
2. 核对本轮可访问的原件和对应数据集业务日期。数据表日期、文件日期、下载时间及不同版本分开记录；不能用修改时间或另一张表的最大日期代替。
3. 最大日期不证明区间内没有缺口。依据用户要求选择新增日期、明确缺日或修订文件，不因缺少同步账本就全历史重下。
4. 已有可信任务记录时沿用；没有记录时以当前文件清单建立本轮范围，不猜测历史下载成功状态。

## 选择与执行

- 日文件按约定日期筛选；年汇总文件按覆盖范围及版本比较。
- 无日期快照比较来源、路径、字符串文件编号、大小及已有成果。同名同大小只是筛选线索。
- 分享缺少可靠修改时间或内容摘要时，说明无法识别所有等大小修订；只在用户要求范围内重新核验。
- 先枚举，再选择需要的文件；每件沿固定目标处理，记录已受理、待核对、已下载及失败状态。
- 使用当前可用单文件动作逐件推进，文件数、字节数和时间按本轮范围控制。没有批量能力时不调用未登记的同步程序。

## 单件完成条件

来源与目标已固定 → 转存结果核对 → 下载实际文件 → 核对大小与SHA-256 → 保存成果和成功记录。

转存受理或下载进程结束均不是单件完成。目标目录中的旧文件不能证明本次新任务成功；本地文件缺失或摘要不符时保留异常，不推进成功日期。

达到本轮限额时报告剩余缺口，不把限额中断说成无更新。正式入库需另走当前材料与数据库入口，以真实提交及固定快照为依据。
