# BD AGENTS 固定基础算法直接入 WFD

## 已确认的数据线路

`BD AGENTS 会话工具 → WFD 固定快照读取 → 注册固定算法 → 一次独立派生核对 → WFD R1 正式写入 → 固定读回与版本关联`

该线路与采集、接口源、文件的原报管道分开。算法产物已经是结构化数据，不再经过原报六维路由、五步加工、材料重新保管或人工计算审批。算法只通过 AGENTS 工具发起；前端只读显示算法、运行状态和结果。

## 工具与职责

- `bd.session.capabilities`（会话工具目录）和 `algorithms.contract`（算法独立接口契约）负责只读发现。
- `algorithms.calculate`（固定算法计算）从 WFD `fixed_snapshot`（固定快照）执行，任务完成后自动调用独立核对与 WFD 发布者。
- `algorithms.publish`（原发布请求恢复）不重算，仅核对同一成功任务及原 WFD 请求的未知或中断结果。
- `algorithms.status`（算法结果只读）仅返回已保存的原任务，不触发计算或 WFD 写入。
- `R1HandoffService`（既有结构化交接服务）复用数据文档校验、WFD 提交、状态恢复与固定读回，允许真正的固定算法证明替代原报加工计划；不向 AGENTS 开放任意记录写入。

## 独立核对的最低要求

核对原计算任务、方法编号与版本、实现版本、冻结输入摘要、WFD 产品和快照身份、来源行与输出行一一对应、业务时间、单位、数据类型、值状态、业务键唯一性、结果摘要。无法证明任一必需条件时拒绝本次派生写入，保留原任务及具体错误码。读取 WFD usage_status（使用治理状态）确认发布没有被明确暂停；目标是否正式发布由 WFD 原权威决定。

不能以计算任务成功代替 WFD 发布成功。仅 R1 原请求处于 associated（完成正式关联）、无待核行且完成固定读回时，AGENTS 报告写入成功；未知结果不换号重送。

## 固定算法目录

`ma`（算术移动均线）、`macd`（指数平滑异同均线）和 `bullish_engulfing`（看涨吞没）复用已有固定实现。每个算法有独立 `methodId`（方法编号）、参数、输入字段和输出字段。其他未启用的已登记方法保留 blocked（不可执行）状态。

`source_observation_ma`（观测均线）是基础算法目录的一节，但 **WFD 固定快照版本尚未实现**，保持 blocked（不可执行），不能借旧批次计算链补位。

## 保留的技术边界与未完成验收

固定算法不再要求人工采用和逐次业务审批，但运行 Python（计算执行器）仍需要宿主已有的执行许可与固定代码摘要匹配。该许可不是一条新的算法业务审核流。

本次只修改分支中的源码，不覆盖 WFD 已发布历史快照。本轮尚未完成完整 TypeScript 编译、真实 WFD 写入和失败恢复端到端测试；这些必须先通过再合入主分支。
