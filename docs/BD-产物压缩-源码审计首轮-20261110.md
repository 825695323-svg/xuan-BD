# BD 产物来源与压缩改造审计（首轮源码核对）

> 基线：`codex/baidu-skill-metadata-archive`。此表依据可读取的源码登记真实产物产生点；不是本地目录扫描统计，也不是可立即删除清单。禁止根据文件年龄、扩展名或“已上传”的文字直接删除原件。

## 1. 产物分层

| 位置 | 当前写入或保存机制 | 处理裁决 | 需要证实的删除前置条件 |
|---|---|---|---|

| `platform/runtime/file-workspace.ts` | 每次任务产生 `.direct-UUID` 暂存，按任务生命周期清理或登记延迟回收 | **复用现成清理**，不做全盘扫描删除 | 无文件引用、无未决任务、工作区身份一致 |

| `modules/collection/cloud-custody.ts` 与 `plugins/storage/baidu-drive.ts` | 受控归档记录、网盘上传/盘内复制和远端元数据核对 | **网盘归档**：不新增独立 CLI（命令行）逻辑；复用 `baidu.drive`（百度网盘技能） | 上传/复制回执与 `ls`（列目录）核对文件名、字节长度及 `fs_id`（远端对象编号）；此证明不是内容 SHA-256 核验 |
| `wfd/product/wfd_sdk` | WFD 的 DuckDB/Parquet（查询引擎/列式数据）、Manifest/Snapshot（清单/固定快照）产品实现 | **永久保留正式发布的数据与不可变清单** | 不自动归档或删除正式快照、清单及读取必需的引用 |

## 2. 首轮结论

1. 首先减掉重复的**内容拷贝**，不是先减索引、谱系和恢复证据。转换结果既可被 R1 使用，也可被检索片段化使用，不能一刀切取消。
2. 百度网盘归档将 `uploaded_metadata_checked`（上传后元数据确认）与 `restored_verified`（明确下载后字节核验）分离；仅凭前者不能证明云端字节与本地 SHA-256 一致。
3. 当前 `TemporaryRetention`（临时保留）已有 3 天生命周期和引用保护。短期不另建自动删除程序，避免两套清理器互相删除恢复现场。
4. 本轮只列源代码证据，**未实施真实文件迁移、自动清盘或数据库大块删除**；需要先通过隔离测试和实际 WFD 固定读回。

## 3. 下轮源码改造顺序

1. 先修复归档 Skill 的行为测试，对“不下载”的新要求进行验证，旧完整字节读取断言不可假装仍成立。
2. 对 `conversion_artifacts`（转换产物账本）逐项证明引用与消费端，再对可重建、不被引用的转换中间副本设置回收点。
3. 将正式结构化结果写入 WFD 后的重复本地产物纳入清单核对，先标记候选，不直接删除。
4. 大文件归档通过现有百度网盘技能，远端文件元数据确认成功后仅解除**确已无引用**的临时空间；未决归档、账本引用、原始证据和 WFD 正式数据禁止自动删除。
