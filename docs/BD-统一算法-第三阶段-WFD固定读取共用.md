# Xuan BD 统一算法第三阶段：财务与宏观共用 WFD 固定行选集

## 完成内容
- 新增 `modules/financial/wfd-fixed-selection.ts`（统一 WFD 固定行选择器），调用既有 `R1Workspace.readProduct`（R1 固定产品读取端口），无新的数据库、网络或后台读取服务。
- 在财务 `projectFinancialFixed`（固定财务算术）和宏观 `projectMacroYoYPolars`（Polars 宏观同比）里复用这一选择器，不再维护两套分页、连接、业务键的重复读取逻辑。
- 逐个固定 `snapshotId`（快照）、`productId`（产品）、`businessKeys`（业务键），宏观再固定 `recordVersions`（记录版本）。拒绝 latest（最新指针）、同一快照重复业务键、WFD 返回身份漂移、连接身份变化、循环游标、超过扫描预算和缺失的选中行。
- 从 WFD 实际读到的记录重新生成 `selectedRowsSha256`（所选来源行内容摘要）和 `recordVersions`（当次返回的记录版本），不采用调用方填入的行摘要。
- 该端口只保证固定快照内容和实际返回身份，不将公开时间自动视为历史可知资格；用途资格、金融语义、独立数值核验与正式发布保持原有职责。

## 行为变化与兼容
- 财务旧输入和宏观旧输入外部请求形式不变；仍只通过原来的 WFD 数据服务读取，原有算法程序和版本身份不变。
- 新验证会拒绝过去可能被悄悄采用的“同一业务键重复记录/分页异常”，属于更严格的失败封闭行为。
- 原 `PolarsFixedService`（Polars 固定服务）及历史任务未删除，新 `algorithms.calculate`（算法统一执行入口）仍未启用这三类迁移中算法，也未添加第二套任务账本。
- 本次没有动真实 WFD 快照、用户材料、百度网盘或历史数据库内容。
