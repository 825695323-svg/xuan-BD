# Xuan BD 前端界面与复用组件规范（V1）

适用范围：`apps/web/src/` 中所有新增或修改的业务页面。此文件是源码维护约定，不定义新的数据库、任务状态或 AGENTS 执行职责。

## 1. 复用顺序

1. **页面布局**：优先使用现有 `WorkspaceLayout`（工作区布局）及 `data-page`、`data-nav`、`page-panes`（三栏业务区）类；不要在页面里复制一份四栏尺寸、拖动器或响应式规则。
2. **对象详情**：三栏页面使用 `ObjectDetailPanel`（对象详情外壳）、`DetailHeader`（详情标题与主要状态）、`DetailFacts`（关键事实）、`DetailSection`（内容分区）及 `DetailDiagnostics`（折叠技术信息）。对象选择继续使用 `useObjectSelection`（带目录就绪校验的选择状态）。
3. **页面原语**：从 `apps/web/src/ui/PageUI.tsx` 复用：
   - `PageHeading`（标题与说明，支持 h2/h3 层级）
   - `PageSearch`（有可访问名称的搜索框，`compact` 用于目录栏）
   - `PageEmpty`（空结果、读取中与能力不可用；`state` 必须匹配真实状态）
   - `PageActions`（操作按钮分组）
   - `PageButton`（静态视觉类型：quiet/primary/danger；默认 `type="button"`）
   - `PageField`（字段标题、控件与帮助文本）
4. **现有控制组件**：`Controls.tsx` 的 `IconButton`（有可访问名称的图标按钮）、`SelectMenu`（下拉选择）、`Modal`（对话框）、`ErrorNote`（业务失败提示）继续复用；不要新增平行弹窗/选择/提示实现。
5. **业务专用控件**：只在公共组件不足以表达明确业务语义时创建，且必须说明不能复用的原因；不得把 R1、WFD 或来源协议塞入通用视觉组件。

## 2. 主题与尺寸的唯一来源

- 主题颜色从 `apps/web/src/styles.css` 的 `:root` 与 `:root[data-theme="dark"]` 获得。正文 `--ink`，辅助说明 `--muted`，次要信息 `--weak`，背景 `--surface` / `--surface-2`，边线 `--line`，交互 `--accent`，失败 `--danger`，成功 `--status-green`，警告 `--status-warning`。使用语义，不直接写固定浅色/深色值。
- 业务区间距使用 `--ui-space-1` 到 `--ui-space-5`（4/8/12/16/24px），控件高度 `--ui-control-height`（36px），圆角 `--ui-radius-control`（8px）与 `--ui-radius-panel`（12px），字号 `--ui-title-size` 与 `--ui-body-size`。
- 现有会话排版、K 线画布、复杂 R1 表格有专用布局，不强制替换为数据页单一高度。通用组件只负责共有的视觉，不擅自更改数据密度或业务功能。
- 样式复用遵循：已有主题变量 → 已有公共类 → 公共组件 → 页面专用 CSS。新页面不得复制 `.data-search`、`.primary-button`、`.ui-dialog` 的声明再覆盖一份。

## 3. 状态、交互与国际化

- 读取中用 `<PageEmpty state="loading">`，空列表用 `<PageEmpty>`，未装配/不可达用 `<PageEmpty state="unavailable">`。接口失败用 `ErrorNote`，不能把失败显示成“暂无数据”。
- 状态标签区分任务、保管、材料与来源检查；通用任务状态统一调用 `taskStateText` / `TaskState`（任务状态显示），不能每页复制状态映射。
- 使用 `useWords()`（中英文双语输出）或统一词典；保留稳定的对象/状态 ID，不把翻译后的可见文本当成业务键。日期和数字统一在展示层格式化，不改写原始业务值。
- 图标按钮必须有 `aria-label`（无障碍名称）；输入框必须关联可读标签；异步提交时控制重复请求，明确未确认回执，不能因视觉状态假定后端成功。
- 选中项使用 `aria-current` / `aria-pressed` 等语义；键盘可达、可见焦点；危险操作不能仅以颜色传达区别。
- 新 UI 不增加 AGENTS 主动动作、数据库状态复制或新轮询任务；视图只调用现有公共业务接口。

## 4. 新页面最小模板

```tsx
import { useState } from 'react';
import { PageActions, PageButton, PageEmpty, PageHeading, PageSearch } from './PageUI';
import { ErrorNote, useWords } from './Controls';

export function ExampleReadOnlyPage() {
  const words = useWords();
  const [query, setQuery] = useState('');
  const items: string[] = []; // 实际数据由页面已有的业务接口提供
  return <section className="data-panel">
    <PageHeading title={words('对象列表', 'Objects')}
      description={words('展示已读取的对象。', 'Objects already loaded.')} />
    <PageActions><PageButton onClick={() => setQuery('')}>
      {words('清除筛选', 'Clear filters')}
    </PageButton></PageActions>
    <PageSearch label={words('搜索对象', 'Search objects')} value={query} onChange={setQuery} />
    {!items.length && <PageEmpty>{words('没有匹配记录', 'No matching records')}</PageEmpty>}
  </section>;
}
```

`ErrorNote`（错误提示）在真实读取失败时使用，不需要为了模板展示制造错误状态。

## 5. 验收

新页面合并前必须检查：深色/浅色主题、桌面/窄屏、标题与搜索、空/加载/失败三种状态、键盘焦点、选中/详情联动、按钮禁用与异步回执；至少执行 `npm run repo:check`（仓库可重建性检查）、`npm run build`（类型检查与构建）和相关组件/业务回归测试。

本轮迁移的首批页面：接口源、采集源、算法目录、数据库列表、基础算法只读展示。未迁移的复杂报表与 R1 页面沿用原有业务结构，后续按需逐项替换，不允许一次性重写。
