# Xuan BD 前端界面与复用组件规范（V1）

适用范围：`apps/web/src/` 中所有新增或修改的业务页面。此文件是源码维护约定，不定义新的数据库、任务状态或 AGENTS 执行职责。

## 1. 复用顺序

1. **页面布局**：优先使用现有 `WorkspaceLayout`（工作区布局）及 `data-page`、`data-nav`、`page-panes`（三栏业务区）类；不要在页面里复制一份四栏尺寸、拖动器或响应式规则。
2. **对象详情**：三栏页面使用 `ObjectDetailPanel`（对象详情外壳）、`DetailHeader`（详情标题与主要状态）、`DetailFacts`（关键事实）、`DetailSection`（内容分区）及 `DetailDiagnostics`（折叠技术信息）。对象选择继续使用 `useObjectSelection`（带目录就绪校验的选择状态）。
3. **页面原语**：从 `apps/web/src/ui/PageUI.tsx` 复用：
   - `PageHeading`（标题与说明，支持 h2/h3 层级）
   - `PageSearch`（有可访问名称的搜索框，`compact` 用于目录栏）
   - `PageEmpty`（空结果、读取中与能力不可用；`state` 必须匹配真实状态）
   - `PageActions`（操作按钮分组）
   - `PageButton`（静态视觉类型：quiet/primary/danger；默认 `type="button"`）
   - `PageField`（字段标题、控件与帮助文本）
4. **现有控制组件**：`Controls.tsx` 的 `IconButton`（有可访问名称的图标按钮）、`SelectMenu`（下拉选择）、`Modal`（对话框）、`ErrorNote`（业务失败提示）继续复用；不要新增平行弹窗/选择/提示实现。
5. **业务专用控件**：只在公共组件不足以表达明确业务语义时创建，且必须说明不能复用的原因；不得把 R1、WFD 或来源协议塞入通用视觉组件。

## 2. 主题与尺寸的唯一来源

- 主题颜色从 `apps/web/src/styles.css` 的 `:root` 与 `:root[data-theme="dark"]` 获得。正文 `--ink`，辅助说明 `--muted`，次要信息 `--weak`，背景 `--surface` / `--surface-2`，边线 `--line`，交互 `--accent`，失败 `--danger`，成功 `--status-green`，警告 `--status-warning`。使用语义，不直接写固定浅色/深色值。
- 业务区间距使用 `--ui-space-1` 到 `--ui-space-5`（4/8/12/16/24px），控件高度 `--ui-control-height`（36px），圆角 `--ui-radius-control`（8px）与 `--ui-radius-panel`（12px），字号 `--ui-title-size` 与 `--ui-body-size`。
- 现有会话排版、K 线画布、复杂 R1 表格有专用布局，不强制替换为数据页单一高度。通用组件只负责共有的视觉，不擅自更改数据密度或业务功能。
- 样式复用遵循：已有主题变量 → 已有公共类 → 公共组件 → 页面专用 CSS。新页面不得复制 `.data-search`、`.primary-button`、`.ui-dialog` 的声明再覆盖一份。

## 3. 状态、交互与国际化

- 默认视图用有来源依据的名称、数值、单位和可执行的操作回答用户当前的问题。记录编号、连接身份、散列值、协议码及原始响应按核对需要展开。数据缺失、结果不完整或操作失败时，直接说明对当前结果的影响。
- 读取中用 `<PageEmpty state="loading">`，空列表用 `<PageEmpty>`，未装配/不可达用 `<PageEmpty state="unavailable">`。接口失败用 `ErrorNote`，不能把失败显示成“暂无数据”。
- 状态标签区分任务、保管、材料与来源检查；通用任务状态统一调用 `taskStateText` / `TaskState`（任务状态显示），不能每页复制状态映射。
- 使用 `useWords()`（中英文双语输出）或统一词典；保留稳定的对象/状态 ID，不把翻译后的可见文本当成业务键。日期和数字统一在展示层格式化，不改写原始业务值。
- 图标按钮必须有 `aria-label`（无障碍名称）；输入框必须关联可读标签；异步提交时控制重复请求，明确未确认回执，不能因视觉状态假定后端成功。
- 选中项使用 `aria-current` / `aria-pressed` 等语义；键盘可达、可见焦点；危险操作不能仅以颜色传达区别。
- 新 UI 不增加 AGENTS 主动动作、数据库状态复制或新轮询任务；视图只调用现有公共业务接口。

## 4. 新页面最小模板

```tsx
import { useState } from 'react';
import { PageActions, PageButton, PageEmpty, PageHeading, PageSearch } from './PageUI';
import { ErrorNote, useWords } from './Controls';

export function ExampleReadOnlyPage() {
  const words = useWords();
  const [query, setQuery] = useState('');
  const items: string[] = []; // 实际数据由页面已有的业务接口提供
  return <section className="data-panel">
    <PageHeading title={words('对象列表', 'Objects')}
      description={words('展示已读取的对象。', 'Objects already loaded.')} />
    <PageActions><PageButton onClick={() => setQuery('')}>
      {words('清除筛选', 'Clear filters')}
    </PageButton></PageActions>
    <PageSearch label={words('搜索对象', 'Search objects')} value={query} onChange={setQuery} />
    {!items.length && <PageEmpty>{words('没有匹配记录', 'No matching records')}</PageEmpty>}
  </section>;
}
```

`ErrorNote`（错误提示）在真实读取失败时使用，不需要为了模板展示制造错误状态。

## 5. 验收

新页面合并前必须检查：深色/浅色主题、桌面/窄屏、标题与搜索、空/加载/失败三种状态、键盘焦点、选中/详情联动、按钮禁用与异步回执；至少执行 `npm run repo:check`（仓库可重建性检查）、`npm run build`（类型检查与构建）和相关组件/业务回归测试。

本轮迁移的首批页面：接口源、采集源、工具目录、数据库列表、MACD（指数平滑异同移动平均）。未迁移的复杂报表与 R1 页面沿用原有业务结构，后续按需逐项替换，不允许一次性重写。

## 6. 视觉验收基线（字体、浮层与窄屏）

- 默认 `fontScale=1`（字体缩放倍数）对应页面根字号 15px；`--ui-meta-size`（信息标签字号）和 `--ui-caption-size`（辅助说明字号）需保持最低约 12px 的可读性。用户自行缩小字体时尊重明确设置，不用页面硬编码覆盖缩放。
- 标题、正文、次要信息按语义层级使用 `--ui-title-size`（标题）、`--ui-body-size`（正文）、`--ui-meta-size`（密集标签），不要在新增卡片上写 `.63rem` 等不便阅读的临时值。
- 普通操作按钮和对话框按钮目标高度至少 `--ui-control-height`（36px）；独立图标按钮按场景使用 `IconButton`（图标按钮），不可因文字换行变成不可点击的覆盖区域。
- 所有悬浮菜单优先使用 Radix Portal（挂载到当前可见画布或对话框的浮层）：必须设置 `collisionBoundary`（避让范围）、`collisionPadding`（边距）；不以页面自身 `position:absolute`（绝对定位）假设空间足够。菜单允许内部滚动，不能横向超出视口。
- `WorkspaceLayout`（工作区布局）按 `workspace-content`（实际业务内容区）宽度调整多栏，而非只看浏览器总宽度；窄屏保留目录访问入口，不能简单把来源与工具导航隐藏。Agent 抽屉作为覆盖层，关闭时入口停靠在专用侧边栏，必须为控件预留空间，不能悬浮遮挡搜索、表单或业务卡片。
- 长 `Modal`（对话框）在小屏里必须自己滚动、按钮可访问，不通过全窗口溢出强迫用户滚动底层页面。
- 视觉测试 `node scripts/visual-ui-audit.mjs`（浏览器截图与几何校验）：使用不连接后端的真实 React 页面夹具；验证浅色/深色、多个窗口宽度、弹层、弹窗、标题/信息字号、控件尺寸及边界。截图与测量结果仅存持续集成临时产物，不进入 Git。
- 自动视觉夹具用于证明共享组件结构没有回归，**不能代替**带真实本机数据的逐页人工检查；未覆盖的业务页面和操作路径需明确列为剩余验收范围。

## 7. 三页详情紧凑化边界

接口源、采集源、算法页共用 `ObjectDetailPanel` 的标题、最多三项摘要和同一详情滚动区；当前读取/操作异常使用顶部 `notices`，不能为了压缩页面折进历史诊断。诊断默认折叠，切换对象重新折叠；标题、章节说明按容器换行，操作与折叠入口继续保留可访问尺寸。

接口源摘要保留能力、路由和最近检查，启用/主备配置不是运行成功。采集源摘要保留配置、渠道与语言、登录态，当前能力、检查原因和本页缺少执行回执的限制展开显示。算法保留定义、计算配置、关联产物、准入与执行四个专业区：参数是登记默认而非已保存作业配置；产物是定义关联而非实际生成回执；准入可用不等于运行成功。当前缺输入等阻断展开，公式、使用限制与实现来源按需展开，不从空目录推断从未运行。

这一阶段仅调整展示与已消费字段校验，不新增 API、权限、自动动作、逐对象会话或任务状态。真实浏览器验证必须保留原对象选择/目录失败/会话草稿回归；几何验证保留原始元素矩形，并独立求视口与滚动祖先的可见交集，不能先把矩形裁进合法边界再宣称通过。

## 8. 主动对象引用与草稿边界

三页的“当前浏览”标签仅展示选择。只有明确点击“问一问”、核对预览并选择“加入当前草稿”，才追加 `bd.ui-object-reference/2` 白名单 JSON 文本：页面、对象种类/编号/显示名称，以及接口源的明确市场身份。该引用不是文件附件、事实验真或执行授权；不带任意目录详情、凭据、运行参数或环境路径，不自动发送、创建会话、跳转页面或执行任务。

预览冻结对象修订、会话/分支与本地资料资格。目录未就绪、对象失效、只读/冲突草稿不能加入；切对象/市场/页/会话或资格变化后须取消重选。最终追加由现有会话管理器同步核最新缓存与精确分支，读取其真实 Drafts 缓冲，不使用旧 React 渲染文本；同一 scope 的既有持久化处理迟到回执和保存错误。成功提示只表示本地已追加，未发送，持久保存状态仍以输入框为准。取消不写，重复确认不追加副本，超长草稿拒绝而不截断。

这不是逐对象独立会话，也不改变数据库页已有引用工作流（只共享并发引用互斥）。真实浏览器验收与明确标注的服务事件/管理器故障反例分别记录，不把通过 Modal 后台 inert 限制的程序调用冒称真实用户切换。任务中心改造仍属下一阶段。

## 9. 真实多任务中心

任务中心与会话共用 App 唯一的 `useConversationTasks`，仅消费既有 TaskService 的 GET 与 SSE，不从聊天文本反推任务，不创建新任务库。清楚区分未选择会话、读取中、已核空列表、读取失败与过时快照；断流保留上次记录并标注过时，刷新只重读/重连，只有真实 SSE 完整快照解除断流状态。任务依原持久序号合并，旧 GET、旧连接和旧会话/本地资格回包不得覆盖新视图；撤权立即清私有记录。

当前范围为会话级非 Pi 对话任务，不伪称按所选对象或分支过滤。受理/运行、等待/待处理、已结束记录分组与原状态分开：暂停、中断、等待核对不当作完成；失败是已结束记录而不是成功。保留原任务标题、阻断、错误、报告进度、结果摘要和只读身份引用；无报告进度不造百分比，记录查看不批准、不重试、不恢复、不派发或改写草稿。服务结果字段按既有任务契约显示，不把现有窄解析器称为任意 JSON 的完整验证。

测试以明确 synthetic 的隔离运行时经现有 TaskService 产生真实状态，不手写任务表、不调用供应商或模型。真实浏览器覆盖多任务、迟到 GET 与 SSE、断流及手动重连、会话切换和无额外任务/草稿改写；未渲染代次与畸形事件窗口另由明确传输故障组件测试覆盖，分别报告。阶段1–3选择、详情与主动引用回归保留；不包含已取消的设备断电和跨平台耐久验收。


## 10. 对象引用的业务版本与诊断边界

引用仅摘取当前页面已读到的类型化 `versionRefs`、`diagnosticRefs` 和 `businessScope`。接口源分开记录整份来源设置文档 revision 与插件 version，以及市场 UI 编号和实际 scopeId；采集源仅引用明确配置 configuredOperation 与已登记操作（不是已选择执行意图），不把静态主题/地区标签当实际覆盖。算法分别引用登记清单版、定义集合版和明确固定的数学 methodVersion；实现有自己的 version 才引用，不能拿数学版代替。未选具体计算配置保持 unknown，不从定义列表取第一项。

SourceCheck 的 id 是对象编号，不是历史异常编号。引用只表达最新检查观察（对象、检查时刻、配置修订、有效期和服务当前投影 reportedStatus），稳定异常编号未知；时间须为严格UTC并通过日期往返和起止顺序校验，非法值未知；过期、配置修订不匹配、缺有效期各自明确，任何状态都不构成执行资格。页面已有检查服务可能把旧结果降为 partial，引用保留回包事实而不恢复旧 passed。预览冻结这些字段，确认前再次构造并比较；即使只有有效期跨界也拒绝追加旧预览，须重新选择。配置或观察更新沿统一对象修订失效机制。

本投影不选取 reason 全文、原始 URL、凭据/token、参数、文件路径字段，也不复制静态覆盖推断；这不是对任意用户命名/显示标签的通用秘密检测。缺失字段明确 unknown；已有 /1 草稿仅保留旧文本，不自动迁移或补充。登记标签与版本是引用来源，不是运行回执、历史事实验证或新授权。

## 11. 任务查找与明确恢复（增量）

独立会话页和嵌入工作台复用同一 `TaskCenter` 与 App 的唯一任务 GET/SSE feed。查找只在当前已读取会话内按标题、编号、动作及状态定位，不查询全局任务，不按页面对象推断所属关系。切换会话或本地资料代次会重置查找与操作预览；查看记录、筛选、刷新及 SSE 重连都不恢复执行。

“查看恢复操作”先读回现有任务详情并核固定任务身份、版本、运行代次及会话。只有用户在预览中明确选择，才请求原 `/tasks/:id/command` 的 `resume` / `retry` 或 `/tasks/:id/recover`。继续/重试可能实际执行并产生费用或外部影响，原 TaskService 的未知效果、依赖、停止、预算、派发权限与运行时审批仍决定是否受理；UI 不批准权限、不解除停止、不接受成果审核。状态候选不承诺任务一定可以执行。`recoverySupported` 只表示已注册运行时有原身份核对接口，不代表事实已核实或执行授权；核对入口不重新派发原外部动作，但可能更新原任务的核对记录，并非纯只读。无支持时不伪造恢复能力。

预览冻结当前任务版本和本地资料资格，确认前再次比对；单次点击锁阻止重复提交，版本冲突或未确认回执要求先读回，不自动重试。已发出的请求不能因切换页面而宣称已取消。现有端点沿原本机私有资料门禁，未新增逐会话 ACL；本增量保证 UI 只对当前会话精确任务发起操作，不将此称为后端跨会话授权机制。原页面只读记录及任务成果展示保持，不从聊天文本生成任务，不新增任务数据库或运行时。

恢复增量的隔离测试使用明确 synthetic TaskService runtime：真实创建、暂停、继续、失败重试、原 effect 核对与 PermissionService deny，不调用供应商或模型。浏览器资格失效反例为宿主同协议 lifecycle 通知故障注入，不冒称人工停用或实际资料解绑；设备断电/跨平台耐久验证不在本增量范围。
