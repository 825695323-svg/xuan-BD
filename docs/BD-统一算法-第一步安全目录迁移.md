# Xuan BD 统一算法：第一步安全迁移（方法目录，不切断现有计算）

## 目的

把“固定算法”与“本地算法”统一为同一个 **BD AGENTS（BD 会话代理）算法方法目录**。固定是方法属性，Python（本地算法执行器）与 Polars（本地表格计算引擎）是执行技术，不是两条业务主线。

## 本次已落地的源码

- `algorithms.contract`（统一算法契约）复用已有 `ALGORITHM_METHODS`（当前 Python 算法表）和 `FIXED_CALCULATION_METHODS`（旧 Polars 固定方法表），用一个目录展示 MA（移动均线）、MACD（指数平滑异同平均线）、严格看涨吞没，以及财务单季/近十二个月、宏观同比和观测均线的迁移状态。
- 旧 `observation_ma20`（Polars 20 期均线）在新目录只作为 `source_observation_ma`（观测均线）的历史方法别名，**不产生第二个新算法方法 ID**。
- `algorithms.capabilities`（算法能力发现）也返回 `methodDirectory`（统一方法目录），不必绕到旧固定计算 HTTP 接口查询有哪些方法。
- 真正已经采用的本机 Python 方法仍按原代码版本运行；未完成 WFD（金融数据仓库）冻结输入与独立核验的 Polars 方法全部显示 `blocked`（尚不可执行）。`algorithms.calculate`（统一算法新任务动作）遇到这些方法在写数据库或创建任务前报 `ALGORITHM_METHOD_NOT_MIGRATED`（尚未完成迁移），不冒充可执行。
- BD AGENTS 会话能力合同移除旧 `data.r1.submit`（模型直送正式 R1 数据），发布只能按现有独立核验与宿主权限办理。

## 为什么这一步不关闭旧 Polars 入口

**不允许在新适配器未完成时让财务和宏观计算突然不可用。** 因此本 PR **不更改** `FixedCalculationService`（旧固定计算服务）、`PolarsFixedService`（旧 Polars 计算任务服务）及旧任务保存方式。新目录统一，但两个实现仍在并存的迁移期；Archify（架构图）应将旧路线画为“迁移中／待收敛”，不能画成已关闭。

真正关闭旧入口的改动及旧任务只读验证，暂存于草稿 PR #13；只有在新 Polars 执行适配器和统一发布链路经充分验收后才能合并。

## 下一步必须完成

1. 财务、宏观和观测均线通过真实 WFD 固定快照与记录版本读取，冻结定义、单位、期间、可得时间及多条来源记录。
2. 复用旧 Polars 数值公式但按统一算法任务契约登记执行器版本，确保算法参数与方法选择不能由外部请求更换实现。
3. 增加相应的独立核验，扩展 `DerivedWfdPublisher`（派生结果正式发布器）对财务和宏观结构化结果的适配。
4. 对每种方法完成固定读回、历史任务查询、故障恢复、错误单位和修订版本拒绝等验收，再切换 `ready`（可用），合并新任务门禁并废止旧入口的新写入。

## 验证边界

专门测试检查目录唯一性、旧别名映射、受控方法标识、统一入口拒绝未迁移方法且不创建任务；原来的固定服务当前仍按未改动行为运行。GitHub 构建和隔离测试不是正式 WFD 或真实金融数据验收。
