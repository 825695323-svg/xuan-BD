## 2. 端到端行为（已经具备的独立工具）

```text
BD AGENTS（BD 会话代理）明确接收来源/文件
  → 来源任务成功、已签发 artifactIds（生成文件编号）
  → artifact.manifest：列出证据角色与归档状态
  → 现有采集/转换/金融语义核对
  → R1（正式结构化交接）→ WFD 固定读回 [独立资格链路]
  → artifact.archive：仅按证据用途上传或复核原远端对象
  → artifact.inspect：核对下游仍否需要本机文件
  → artifact.release：仅对无依赖、本机自有的生成文件显式删除
  → artifact.restore：未来明确需要原件时按原网盘身份和 SHA-256 恢复成新文件引用

五步加工对象另外：
  artifact.candidates.inspect → artifact.candidates.prune
  （冻结分页摘要、无未决 R1/任务引用、数据库事务）
```

**未实现的能力不能暗示已经完成：** 这些工具仍需要 BD AGENTS 或受信操作会话显式调用，并非所有来源一完成就自动按策略归档；来源清单也不会自动识别某条数据已被 WFD 正式接收。旧 `fileRefId`（旧文件引用编号）不会在后台自动改绑到恢复出来的新编号。

## 3. 数据边界

- **本地长期保留：** WFD 正式 Parquet（列式数据）、Manifest/Snapshot（发布清单与固定快照）、必要 SQLite（本地索引）、历史来源身份、任务/定义/证据关系。
- **按需归档到百度网盘：** 不可替代的原始响应、PDF/图片/字幕、时间戳转写证据、真正需要保留的大型来源原件；不重复复制 WFD 已发布的结构化数据。
- **可明确回收：** 远端已确认且本机无下游依赖、身份与摘要匹配的自有生成文件；无任何任务/加工/R1 引用的候选对象。默认只读预览，不进行全目录自动删除。
- **严格不动：** `material_objects`（材料原字节对象）、`r1_original_contents`（R1 原始证据字节）、WFD 正式数据/固定快照、任何未收束任务的恢复现场。
- **容量和校验注意：** 归档阶段的名称/大小/`fs_id` 元数据核对不等于远端字节核验。完整 SHA-256 只在显式恢复时验证。单件归档有现存 256 MiB（兆字节）上限；超限不能声称已归档。`reclaimedLogicalBytes`（候选对象逻辑回收量）不等于 SQLite 数据库物理文件立即变小。
