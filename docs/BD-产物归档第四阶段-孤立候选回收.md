# BD 产物压缩第四阶段：五步加工候选对象的孤立回收

## 完成能力

- `artifact.candidates.inspect`（候选对象只读预览）：分页返回 `candidate_objects`（五步加工候选对象仓储）中没有任何加工步骤、R1 正式交接或任务真实引用的对象摘要、逻辑大小和冻结计划摘要；不读取业务内容、不开网盘。
- `artifact.candidates.prune`（按冻结计划明确清理）：需要完整 `expectedPlanDigest`（预览计划摘要）和受控的 `bd-candidate-storage-maintenance`（数据库候选维护授权），重新核对引用后在数据库事务内删除孤立候选对象。计划变动立即拒绝，保留原对象。
- 若存在任何未收束的 R1（正式结构化交接）状态或活跃加工/算法任务，全部拒绝回收。损坏、缺失、字节长度或 SHA-256 不符的对象保留调查；数据库事务回滚，不部分清理。
- 同时支持旧 `candidate_objects`（普通候选对象表）与新 `candidate_object_layouts` + `candidate_row_blocks`（共享行块布局）。只在确实没有其他布局引用时删除孤立行块，未拆散任何仍在使用的结构化结果。
- 采用每次最多 50 项的固定分页，保持 `nextCursor`（下页游标）并冻结每页计划。无需常驻后台服务。
- 回收操作仅删除候选仓储内的孤立对象：`material_objects`（材料原字节）、`r1_original_contents`（R1 原始证据）、`r1_record_associations`（已核实正式交接关联）、WFD 的 Manifest/Snapshot（清单与固定快照）及 SQLite 其他索引一概不删除。

## 容量结论

回执中的 `reclaimedLogicalBytes`（逻辑释放字节数）是孤立对象的原记录体积，不等于磁盘立即腾出的空间。SQLite 数据文件可能只是获得内部可复用空页；该任务不在工作时执行 `VACUUM`（数据库物理重排压缩），以免加大运行中断和存储风险。

## 验收

隔离测试覆盖共享行块删除后仍有对象可重建、R1 未决时全局拦截、数据损坏回滚、下游未完成任务拒绝清理。构建、TypeScript 类型检查和自动测试通过；真实用户历史 Core 数据库尚未迁移或回收。

## 未执行的高风险操作

- 不对真实 SQLite 数据库执行清理。
- 不替代正式 WFD 固定读回核验。
- 不将远端的元数据确认误报为完整内容一致。
- 不对旧任务自动恢复、强制删除或批量扫描存储。
