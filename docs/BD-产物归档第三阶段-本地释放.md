# BD 产物归档第三阶段：本地可回收性与安全释放

## 完成范围

- 新增 `artifact.inspect`（归档产物回收资格检查）。只按已登记来源任务和 `fileRefId`（文件引用编号）查询历史归档回执、远端文件名/大小/`fs_id`（文件对象编号）及本地消费者。不扫磁盘、不下载远端原件、不主动清理。
- 新增 `artifact.release`（已归档无引用生成产物的明确本地释放）。必须同时满足：来源任务已成功、独立归档回执 `confirmed`（元数据已确认）、原冻结账号一致、远端仍有同编号同大小文件、本机来源是独立的自有 `artifacts`（产物根）普通文件、原内容 SHA-256 一致、没有其他文件引用/材料/加工/检索/R1/任务依赖，且调用者提供冻结 SHA-256。
- 回收调用当前受控任务的文件读/删权限；每次重新检查本地对象身份和引用；删除前持久记录 `artifact_local_releases`（本地释放意图账本），成功后记录 `released`（已释放）。如果回收意图未收束而本地原件消失，则保持不确定，禁止冒充成功。
- 回收后旧 `fileRefId`（原文件引用编号）不被改写，状态变为 `missing`（本地不再存在）；需要内容时明确调用 `artifact.restore`（从冻结网盘对象取回），验证完整 SHA-256 并以新文件编号发布，消费者不得假设旧编号仍能直接读取。

## 不能回收的情况

- 没有已确认网盘原件；网盘账号、路径、文件名/大小/编号变化；本地内容摘要不匹配；文件不属于本应用自有产物根。
- `material_objects`（材料原字节）、`conversion_artifacts`（转换产物账本）、`segment_requests`（检索片段请求）、`processing_plans`（加工计划）、`r1_handoff_attempts`（R1 正式交接）或其他任务/文件引用存在已知依赖。
- `r1_original_contents`（R1 原字节）、`candidate_objects`（五步加工候选对象）、WFD（金融数据仓库）的 Manifest/Snapshot（清单/固定快照）、全库索引、模型文件均不在本次生成文件的删除范围。
- 未经明确行动不会自动在后台清盘；`artifact.inspect` 仅提供审核信息，`artifact.release` 为单件受控删除。

## 自动验收

覆盖同一来源产物的 **归档 → 查询 → 明确回收 → 缺失引用 → 恢复新文件**，并覆盖待处理下游任务、材料持久引用、网盘对象编号变化、错误 SHA-256 和回收中断状态。类型检查及相关隔离测试通过不等于已对真实百度网盘账号、生产 WFD 和实际历史数据库完成验收。

## 仍待完成

1. 结合 WFD 固定读回结果确定可归档的最小来源证据集合，避免产物未被正式接收就被误清理。
2. 对已有 `candidate_objects`（候选对象）和 `material_objects`（材料原件）做保守的空间可回收评估；必须先证明历史重放仍可用，不应直接删除。
3. 在真实网盘账号上验证上传、元数据查询和按需恢复，尤其是源链接失效、文件已删、同名内容变化等场景；没有真实凭据时不可声称上线完成。
