# 仓库保存配方，不保存成品

## 保留

源码、入口、依赖清单与锁、下载地址和字节摘要、构建/启动/验证脚本、配置模板、协议 schema（结构定义）、内嵌数据库迁移、必要回归样本、手工维护文档与界面源素材。

锁文件虽由程序生成，却是重建依据；不能按“生成文件”统一删除。数据库迁移当前通过源码 `database.migrate(...)`（数据库版本迁移）保存，不要求空建一个 migrations 目录。`codegraph.json` 是架构扫描配置，不是生成图册。

## 排除

node_modules、虚拟环境、dist、缓存、临时扫描/图册、工作副本、运行时 SQLite、日志、用户上传、凭据、模型权重和随包二进制。`.gitignore` 只阻止新文件被跟踪，不能自动清除历史已跟踪项；`npm run repo:check` 同时核查 Git 索引。

## 清理边界

本次从当前树移除 `staging/source-replacement-20261109/` 三个旧摘要清单、未被引用的 `staging/wfd_sdk/product_machine.py` 旧副本，以及 WFD 产品目录中两个仅含占位文字的随机文件。旧副本的函数均在正式实现存在，未发现独占业务入口。删除只改变 Git 当前树，不重写历史，不操作用户运行根。

`wfd/product/legacy_samples/old_codec_example.parquet` 被 `wfd/product/tests/test_duckdb_engine.py` 用作旧编码回归输入，不可删除。公式定义、协议示例、界面图片和已引用测试数据继续保留，不能仅凭后缀判断“非工程文件”。

## 验收分层

1. 配方完整性：引用存在、锁匹配、资源版本固定、内置代理规则摘要一致，无误入库状态。
2. 干净环境重建：按 README 下载精确工具链、按锁安装、类型检查和构建。
3. 隔离运行：新运行根创建、基础界面与健康接口、重启身份、既有 WFD / 计算回归。
4. 真实部署：平台图形界面、转录质量、外部模型、账号、数据源与用户库另行验收，不能从前三级推定通过。
