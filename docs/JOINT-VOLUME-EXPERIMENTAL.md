# 显式新建联合提交卷：实验性 SDK 治理

本切片接通 WFD 原生普通发布，以及完整原组的 SDK 暂停、精确票据与候选核验后联合解决；尚不是 BD 用户整组更正闭环。格式为 `wfd.joint-volume.experimental/1`，只能由明确新建的 SDK 调用 `WFDDuckDBPrototype.initialize_new(..., storage_format='joint_experimental')` 创建空卷。

**BD / product-machine 连接入口拒绝该格式，不能选择为用户活跃数据库。** 旧卷不迁、不自动升级、不改变旧读取或单输出更正规则。现有正式库、Mac 现场均未使用。

## 当前支持

- 一份 `catalog/joint-current.json` 指向不可变联合提交对象，绑定实际快照的 HEAD 投影/摘要、用途对象摘要、前驱联合提交、原请求身份/文档摘要和写入 epoch。没有旧 `catalog/state.json` 或可变用途文件作为第二权威。
- 复用现写锁、不可变对象写入和原子替换设施。普通 data-only SDK `submit` 必须显式传 `expected_commit_id`，从 `snapshot_status` 读取。旧 token 不能用来提交新请求，不能以当前值自动补齐；原号回放须核原摘要及原联合前驱，不倒拨当前提交。
- 快照激活不等于正式发布：仍经过原数据服务的合同和固定读回核验、formal receipt、holding 等后置检查。指针翻转前/后失败沿原号状态与 intent 恢复，不创建新提交身份。
- 用途暂停和宿主票据登记要求显式 `expected_commit_id`，同一 CAS 更新治理而不改变当前快照。普通发布继承其不可变引用，损坏对象不当作空。`read`、固定分页与状态查询捕获单次当前用途视图并在返回前核联合提交未变；固定旧快照不因此获得绕过最新治理的权限。

## 明确未支持

公开单独 resolve、写目标/复权锚点登记、compaction、GC、transfer、R2/P5 对该新格式明确拒绝，旧格式保留原行为。拒绝发生在业务写之前，既有锁装饰器仍可能先取写锁。

未开放 BD 真实组修订审批/选库入口、跨页查询统一治理 token、迁移、换主或新历史接口。当前单用户本机仍需要原权限；格式不授权调用者。未来组接入不能把候选提交、审批或准入当作正式完成。

## 兼容保证范围

没有旧 state 文件，因此冻结基线 `974a67d` 的旧引擎 `open_existing` 读/写模式都明确拒绝，实测目录及字节不变；旧显式 `initialize_new` 亦拒非空目录。新代码每次视图核格式标记，混合旧 state/usage 或标记缺损均拒绝。

这不能约束任意旧脚本使用默认构造器自行初始化或直接写文件。禁止混用；新程序发现混合文件不会自动修复或迁移。测试只使用隔离新卷。

## 定向证据

真实合成 WFD 普通发布、固定读回、服务重开、原号恢复、翻转前/后方法级 I/O/回执异常、读取途中另一提交、两个独立 Python 进程同前驱竞争，以及旧卷回归和未支持入口拒绝均在定向测试中核对。首轮异常测试曾误期待异常上抛，实际既有服务返回未正式状态；现按真实返回及原号恢复断言，不改变原错误处理。

测试进程竞争为同机文件锁与 CAS，不是跨机器；方法级故障与服务重开不是断电或跨平台耐久。SDK 的票据测试为合成宿主明确授权，不冒称真实操作者已批准；BD TaskService 审批接入尚未完成。

公开固定快照读取仅接受本次捕获的 joint 提交祖先内已激活的 snapshot；指针翻转前留下的候选文件、commit marker 或 engine receipt 不构成公开可见性。内部候选核验仍可验证不可变文件。该门禁保留候选内部核验与公开可见性的区分。

公开产品发现同样核已激活祖先；未适配的 ProductQuery 和写目标解析对实验卷明确拒绝，避免在固定读取之前返回候选元数据。旧卷路径不变。

## 完整原组 SDK 修复

修复必须来自同一已激活原快照中存储的单个不重叠组，原固定请求的正式回执、intent/status、原发布权限及合同核验均须成立，所有原成员及其完整行版本逐一对应票据与提交前驱；不能凭新声明、小范围票据或相同数量臆造组。跨快照、含多个版本文件导致无法唯一归属、部分行、跨组和额外新行均保守拒绝。旧单输出更正保持旧格式路径。

首次提交与原号恢复共享私有候选核验：真实不可变 snapshot/commit、原冻结计划、四合同、所有成员精确读回、原票据与范围全部通过后，唯一 joint 指针同时绑定新快照、resolved 用途对象和核验凭据。指针前失败仍是旧状态；指针后回执失败则沿原身份补后置回执，不重新翻转、不刷新已提交核验时间。旧错误版本限制继续保留，解决不表示旧值重新可用。

`test_joint_governance.py` 覆盖真实合成双成员流程、缺员/虚构原组、末成员产物缺失、缺发布权限、过期治理 CAS、两独立进程竞争，以及翻转前后原号重开。不是生产供应商、设备断电或跨平台耐久实证。
